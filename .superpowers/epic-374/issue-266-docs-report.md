# Issue #266 config, operator docs, and Helm lane report

## Outcome

Implemented the maintainer-approved fail-closed tenant contract in the assigned
config and operator surfaces:

- `tenants[].tenant_id` is required and must be a hyphenated Entra
  directory UUID/GUID. Hex case is accepted; verified domains, arbitrary
  names, compact UUIDs, braced UUIDs, and whitespace-padded values are rejected.
- Duplicate directory GUIDs are rejected case-insensitively.
- Operator docs state that graph2otel sets the configured directory GUID on
  every token request, restricts the credential to that explicit target, and
  verifies the returned token `tid` before any tenant-labelled collector or
  signal starts.
- `DefaultAzureCredential` selects one ambient application identity for the
  process. YAML `client_id` remains an optional non-secret consistency
  assertion and never chooses or overrides credentials.
- Workload identity uses its platform-injected ambient identity. Managed
  identity remains bound to its Azure home tenant; a configured directory /
  returned `tid` mismatch fails that tenant closed before data is emitted.
- Multi-tenant client-secret/certificate deployments use one process-level
  credential and a multi-tenant app with a consented service principal in
  every listed directory. Credential environment variables are not repeated
  per YAML tenant.
- Secrets remain outside application YAML and the chart ConfigMap.

The Helm schema now enforces the same required hyphenated-GUID contract before
install or template rendering. Helm auth examples and annotations now include
the required ambient `AZURE_TENANT_ID` for environment credentials and no
longer claim that YAML `client_id` can replace `AZURE_CLIENT_ID`.
