## Contract documented

- Normal startup and `graph2otel check` use the same strict validation boundary
  before credentials, checkpoint stores, telemetry exporters, collectors, or
  network clients are constructed.
- Unknown fixed YAML keys fail with their complete path, including tenant
  indexes and literal collector map keys.
- Unknown `G2O_*` variables fail with their exact environment-variable name.
- Diagnostics identify paths or variable names without printing their values.
- Global and per-tenant collector override names must match the generated
  runtime collector inventory; an unambiguous near miss receives a
  `did you mean "..."` suggestion.
- The only dynamic collector environment form is
  `G2O_COLLECTORS__<NAME>__(ENABLED|INTERVAL|SOURCE)`. Structured tenants and
  free-form Pyroscope tags remain file-only.
- `source` is unset or exactly `graph`/`blob`, and applies only to the three
  registry-derived source-switchable names: `entra.directory_audits`,
  `entra.provisioning`, and `entra.risk_detections`. Setting either source on
  another collector is rejected.
- The old `sign_ins` examples were replaced by the real registry name
  `entra.signins.interactive`, so the example configuration remains valid once
  runtime collector-name validation is active.
- The same replacement was applied to every root README and chart values
  example identified by the integrated review. The environment form is now
  `G2O_COLLECTORS__ENTRA.SIGNINS.INTERACTIVE__ENABLED`; the Helm `--set`
  example shell-quotes the argument and escapes the dots in the map key.
- `TestShippedCollectorOverrideExamplesUseRuntimeName` checks the explicit root
  README, chart values, and generated chart README examples against the
  existing `collectorOverrideInventory()`. It adds no collector census.
